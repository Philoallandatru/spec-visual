# 两套 3D 教程的入门可学性审核

审核日期：2026-10-21。源码基线：`324c207`。范围为 `visual-lab/` 的 20 章 NVMe 课程与 `pcie-visual-lab/` 的 7 章 PCIe 物理层演示。

本次通读了两套课程的章节文案、教学控件和相关渲染逻辑；在浏览器 1280 × 720 视口抽查 NVMe 全景、PRP、队列，以及 PCIe 差分、眼图、FFE 和 RX 均衡。PCIe 仓库副本与原工作目录的源文件一致。这是内容和交互的专家走查，没有招募真实初学者，也不是对全部协议条款的合规认证。

## 结论

NVMe 已具备较好的入门教学结构，适合知道 CPU、内存、磁盘基本区别的读者；但导学与图形状态、标注和阅读节奏还存在明显障碍。PCIe 目前更适合有信号完整性基础的人做交互复习，对零基础读者仍偏陡。

内容丰富度已经足够支持入门。下一阶段应优先完善“看懂图、解释术语、跟做一个实验、说明为什么”的过程。保留专业内容，并将公式、寄存器和规范边界放在进阶层。

以下 P1 表示应在作为入门教程推荐前优先处理；P2 表示影响学习效率或理解验证。它们是本次教学审核的优先级，不代表安全漏洞等级。

## 发现

### 1. P1：NVMe 导学步骤与实验状态没有同步

证据：[讲解步骤只更新索引和文案](../src/main.js#L52)、[PRP 场景按实验参数生成](../src/scene.js#L185)、[PRP 第三步的讲解](../src/course.js#L124)。

复现：进入 `#prp`，保持默认 8 KiB、偏移 0，点击第三步“超过两页就需要列表”。左侧说 PRP2 改为指向 PRP List；右侧仍显示两页、PRP2 为数据页、列表条目 0，而且没有列表对象。第 4 步讲 SGL 时也继续显示 PRP 图。

同类情况：`#queues` 从初始状态进入第三步“设备生产 CQ 条目”，SQ/CQ 仍为空，指针仍是 0，实验提示仍为“先写入一条命令”。这些实验可以手动操作，但“播放讲解”本身没有给出对应的完整过程。

影响：初学者无法判断自己是否理解错、是否漏了操作，或者图没有反映讲解。

建议：为导学准备可回放的状态快照，先演示完整案例，再进入自由实验。若某一步需要手动操作，直接提供“加载本步示例”，并说明当前图属于哪个案例。PRP 第三步可用 8 KiB、偏移 256 B；SGL 应有自己的地址与长度描述图。

验收：仅使用“下一步”就能看到本步所描述的状态；回退后文字、图形和读数仍一致。

### 2. P1：关键图形或标签在默认视角不可见

证据：[PCIe 相机适配](../../pcie-visual-lab/src/main.js#L21)、[差分场景默认相机](../../pcie-visual-lab/src/chapters/diff.js#L16)、[NVMe 标签碰撞处理](../src/scene.js#L322)。

浏览器观察：在 1280 × 720 下，PCIe 首章的发送端落在画面左侧之外，文案要求观察的接收波形屏幕在右侧之外；FFE 的部分电平标注被右边界截断。初学者必须先学会缩放或平移，才能找齐文字里提到的对象。

NVMe 全景默认视角中，CPU、CQ 和控制器标签也未显示。代码遇到标签重叠就隐藏后来的标签，没有优先保留当前步骤的高亮对象。

建议：按本章全部关键对象的范围适配相机；保留当前步骤主角的名称，用外置标签或引线解决碰撞。固定“发送端 → 信道 → 接收端 → 观察结果”的初始视图。

验收：不旋转、不缩放就能找到当前讲解中的每个关键对象；至少在常见桌面、窄屏和手机宽度复核。

### 3. P1：PCIe 缺少先修概念，眼图实验又提前暴露后续章节的内容

证据：[第一章导语与要点](../../pcie-visual-lab/src/chapters/diff.js#L5)、[第一章直接列出的 UI 数值](../../pcie-visual-lab/src/chapters/diff.js#L109)、[第三章默认参数与控件](../../pcie-visual-lab/src/chapters/eye.js#L34)、[章节顺序](../../pcie-visual-lab/src/main.js#L10)。

第一章直接使用 Lane、UI、mVpp、GT/s、端接、CDR、LTSSM 和 TS1/TS2。UI 的一句话定义存在于仿真源码注释中，界面没有对应的基础解释。第三章已经让读者选择 11 个 Preset、CTLE 峰化和 DFE 抽头数，相关机制分别在第 4、5 章才展开。

影响：读者可能会移动滑块，却不知道滑块改变了什么、单位表示什么，以及这次只应观察哪个变化。

建议：增加简短预备课，先讲一个符号如何占据一段时间、接收器如何判 0/1、Lane/TX/RX 的关系，再解释 UI、幅度、损耗和误码。第三章先提供简单眼图，只开放一个变量；完成 TX/RX 均衡后再开放完整参数面板。BER、CDR 等首次出现处提供中文解释。

验收：读者不用查外部资料，就能解释“1 UI 是什么”“眼睛变窄意味着什么”“这一步该调哪个参数”。

### 4. P2：FFE 先给公式，缺少可手算、可观察的过渡例子

证据：[FFE 导语](../../pcie-visual-lab/src/chapters/ffe.js#L15)、[四种电平与系数限制](../../pcie-visual-lab/src/chapters/ffe.js#L19)、[默认直接选择 P7](../../pcie-visual-lab/src/chapters/ffe.js#L28)。

开头第二段就给出三抽头公式和 FS，接着同时展示 11 个 Preset；后面又加入 Va/Vb/Vc/Vd、对数、LF 和合法区域。文案虽解释了“去加重”和“预冲”，却没有带读者算出任何一个比特的电平，也没说明为什么发送器能利用序列中的后一个比特。

建议的示例顺序：固定一小串 `0001110`；先用 P4 看原始波形；切到只带去加重的 P1；高亮翻转后的第一个 1 与连续 1 的稳定段；解释两者的差异；最后展示这一小段怎样代入公式。用另一个示例讲预冲，系数合法性留作进阶。

验收：隐藏公式后，读者仍能指出图中哪一段被改变、为什么；展开公式后，可以亲手计算一个采样值。

### 5. P2：NVMe 自动播放的时间不足以支持边读边看

证据：[速度选项](../index.html#L29)、[固定计时推进](../src/main.js#L19)。

默认每 4 秒推进一步，最慢为 6 秒。91 个步骤的正文长度为 37–91 个字符，平均约 58 个字符，尚未计算标题和在图中寻找对象的时间。页面最初是暂停的，也有手动步进，但点击“播放讲解”后容易赶不上阅读。

建议：保留手动步进为主要入口；提供足够长的阅读档位，或根据文本长度确定停留时间；重要动作完成后允许停下来观察。“播放讲解”也应明确是文字与动画播放，避免让读者等待语音。

验收：初学者无需反复暂停或回退，就能读完正文并指出对应对象。具体秒数应通过试学调整。

### 6. P2：NVMe 入门主线中仍过早混入大量实现细节

证据：[全景第三步](../src/course.js#L13)、[全景默认展开的原理](../src/course.js#L17)、[Read 的提交和完成步骤](../src/course.js#L42)、[门铃地址公式](../src/course.js#L96)。

全景课同时涉及 MMIO、DMA、虚拟地址、Namespace/LBA 和 CMB；Read 又带入内存可见性、SQID/CID、Head/Tail 和 PRP/SGL。术语手册已经存在，是优点，但读者仍需不断离开当前讲解查词。许多细节对正确性有价值，却不必成为第一次理解读写流程的门槛。

建议：基础层保留“请求单、数据、回执、交接通知”，每次给中文和缩写；同一份具体读请求贯穿后续章节。将地址公式、屏障和可选能力放在可展开的工程细节中，保留必要的模型假设。

验收：读者读完前几章，可以不背寄存器名，完整复述一次读写；需要深入时仍能找到真实字段和来源。

### 7. P2：PCIe 的“自动寻优”说明与实际评价目标不同

证据：[文案称寻找最大眼面积](../../pcie-visual-lab/src/chapters/eye.js#L29)、[实际搜索只比较峰值失真眼高](../../pcie-visual-lab/src/chapters/eye.js#L50)。

实现比较的是 `peakDistortionEH`，搜索时使用信道、Preset、CTLE 和 DFE 抽头数，没有使用当前噪声、RJ、SJ 或串扰设置，也没有比较眼宽。因此它不是当前全部链路条件下的眼面积优化器。

影响：读者会错误理解“最佳”的标准，并可能把一个简化搜索结果推广到噪声或抖动变化后的情况。

建议：将按钮与说明改成“按仅 ISI 眼高搜索”，明确忽略的因素；或按页面承诺，以当前模型的完整评价结果优化。无论选择哪种方式，都应在结果附近显示优化目标。

验收：按钮文字、解释、评价函数和日志使用同一个目标；调整被声称纳入的参数，应能参与实际评价。

### 8. P2：自测不足以确认读者已经能推理

证据：[NVMe 中断章选择题](../src/course.js#L190)、[NVMe 答题反馈](../src/main.js#L188)、[PCIe 页面呈现流程](../../pcie-visual-lab/src/main.js#L27)。

NVMe 有 20 道题，但部分错误选项明显无关，例如通知合并题中的“数据精度和画质”。答错后直接展示同一段答案解释，也缺少“为什么这个错选项看似合理”的反馈。PCIe 7 章没有对应的理解检查。点击或看完动画无法证明读者能解释因果。

建议：每章设置一道预测题和一个操作任务。例如“未敲 SQ 门铃，设备能否取走新命令”“只加共模噪声，单端与差分波形分别怎样变化”。先让读者预测，再操作验证，最后解释结果；错误选项来自真实误解。

验收：通过者能够说明原因，并在一个稍有变化的案例中再次判断，而非只记住答案位置。

## 应保留的优点

- NVMe 用“问题 → 仓库类比 → 逐步讲解 → 实验 → 误解 → 自测”的结构，主线清楚。
- Namespace 不等于分区、命令不等于数据、完成不等于持久化、超时不等于没执行等关键辨析值得保留。
- NVMe 多数实验已有具体操作提示，PRP 偏移、NLB 越界和 Flush/FUA 掉电实验很适合教学。
- PCIe 的脉冲叠加、眼图和链路四处对比具有教学价值；需要补充观察顺序和基础说明。
- 两套项目都应继续保留规范依据和教学模型边界，让简化内容有可追溯的进阶入口。

## 建议实施顺序

1. 先修导学与图形不一致、默认视角裁切、当前对象标签隐藏，并统一自动寻优的教学承诺。
2. 再补 PCIe 预备课、基础眼图模式、FFE 小例子；调整 NVMe 术语呈现和播放节奏。
3. 最后给每章加“预测 → 操作 → 观察 → 解释”任务，并补充有区分度的自测。

完成这些后再邀请少量真实初学者试学：记录第一次停住的位置、需要查词的次数、能否独立完成任务、能否复述因果。此前的自动化测试和 HTTP 200 只能证明部分功能可运行，不能替代入门可学性验证。
